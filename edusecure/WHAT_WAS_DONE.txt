PART 6 — utils/crypto.py
================================================================================

Adapted from the student's aes_encryption.py but UPGRADED from AES-ECB
to AES-GCM.

WHY THE UPGRADE:
  AES-ECB (Electronic Codebook) encrypts every 16-byte block independently
  with the same key. Identical plaintext blocks produce identical ciphertext
  blocks, so patterns in the data leak through the ciphertext. There is also
  no authentication — an attacker can modify the ciphertext undetected.

  AES-GCM (Galois/Counter Mode) uses a random 16-byte nonce so every
  encryption produces different output even for the same plaintext. It also
  produces a 16-byte authentication tag. If even one bit of the ciphertext
  is changed after encryption, the tag check fails and decryption raises an
  error. This provides both confidentiality AND integrity in one operation.

----------------------------------------------------------------------
FUNCTION: encrypt_aes_gcm(plaintext: str, key: bytes) -> str
----------------------------------------------------------------------

  nonce = os.urandom(16)
  cipher = AES.new(key, AES.MODE_GCM, nonce=nonce)
  ciphertext, tag = cipher.encrypt_and_digest(plaintext.encode('utf-8'))

  Returns a JSON string with three base64-encoded fields:
    nonce      — 16 random bytes, unique per encryption, never reused
    ciphertext — the encrypted payload
    tag        — 16-byte GCM authentication tag

  The nonce never needs to be secret but MUST be unique for every
  encryption under the same key. os.urandom guarantees this.

----------------------------------------------------------------------
FUNCTION: decrypt_aes_gcm(token: str, key: bytes) -> str
----------------------------------------------------------------------

  data = json.loads(token)
  cipher = AES.new(key, AES.MODE_GCM, nonce=base64.b64decode(data['nonce']))
  plaintext = cipher.decrypt_and_verify(ciphertext, tag)

  decrypt_and_verify raises ValueError automatically if the tag does not
  match — meaning the ciphertext was tampered with. This directly addresses
  the assignment incident where an attacker modified a submitted file.

----------------------------------------------------------------------
FUNCTION: compute_hmac(data: bytes, key: bytes) -> str
----------------------------------------------------------------------

  return hmac.new(key, data, hashlib.sha256).hexdigest()

  Computes HMAC-SHA256 over raw bytes. This is the same keyed-hash
  mechanism shown step by step in totp.py (which uses HMAC-SHA1 for the
  TOTP counter). Here SHA-256 is used for stronger collision resistance.

  Returns a 64-character hex string.

----------------------------------------------------------------------
FUNCTION: verify_hmac(data: bytes, key: bytes, expected: str) -> bool
----------------------------------------------------------------------

  actual = compute_hmac(data, key)
  return hmac.compare_digest(actual, expected)

  Uses hmac.compare_digest instead of == to prevent timing side-channel
  attacks. A normal string comparison (==) short-circuits on the first
  mismatched character, leaking information about how much of the digest
  matched. compare_digest always takes the same time regardless.

PART 7 — utils/virustotal.py
================================================================================

Adapted from the student's urlcheckerapi.py.

Changes made:
  - Removed the while True CLI input loop
  - Removed the hardcoded API key (now loaded from settings.VIRUSTOTAL_API_KEY)
  - Split into two clean functions that return dicts instead of printing
  - Added timeout parameters to all requests calls
  - Made it importable by Django views

----------------------------------------------------------------------
FUNCTION: scan_url(url: str) -> dict
----------------------------------------------------------------------

  url_id = base64.urlsafe_b64encode(url.encode()).decode().rstrip("=")
  response = requests.get(f"{VT_BASE}/urls/{url_id}", headers=_headers(), timeout=15)
  stats = response.json()["data"]["attributes"]["last_analysis_stats"]

  VirusTotal v3 requires the URL to be base64url-encoded without padding
  before it can be looked up. The function queries the last_analysis_stats
  from the response JSON and returns:

    {
      "safe":       bool or None,
      "malicious":  int,
      "suspicious": int,
      "message":    str
    }

----------------------------------------------------------------------
FUNCTION: scan_file(file_obj, filename: str) -> dict
----------------------------------------------------------------------

  upload_resp = requests.post(f"{VT_BASE}/files", headers=_headers(),
                              files={"file": (filename, file_obj)}, timeout=60)
  analysis_id = upload_resp.json()["data"]["id"]

  for _ in range(10):
      time.sleep(15)
      report = requests.get(f"{VT_BASE}/analyses/{analysis_id}", ...).json()
      if report["data"]["attributes"]["status"] == "completed":
          ...

  Uploads the file to VirusTotal, gets back an analysis_id, then polls
  every 15 seconds up to 10 times (approximately 2.5 minutes total).
  Returns the same dict shape as scan_url.

  If the scan does not complete in time, returns safe=None with a warning
  message so the submission is not silently marked safe.

PART 8 — accounts/models.py
================================================================================

Extended Django's AbstractUser with three extra fields:

  class User(AbstractUser):
      ROLE_CHOICES = [
          ('student',  'Student'),
          ('lecturer', 'Lecturer'),
          ('admin',    'Admin'),
      ]
      role        = models.CharField(max_length=20, choices=ROLE_CHOICES, default='student')
      totp_secret = models.CharField(max_length=64, blank=True)
      mfa_enabled = models.BooleanField(default=False)

  role        — distinguishes students, lecturers, and admins for later
                permission-based views
  totp_secret — base-32 encoded TOTP secret provisioned during MFA setup;
                blank until the user completes setup
  mfa_enabled — False until the user scans the QR code and confirms with
                a valid token; the two-step login only triggers when True

Three helper methods:

----------------------------------------------------------------------
METHOD: generate_totp_secret()
----------------------------------------------------------------------

  self.totp_secret = pyotp.random_base32()
  self.save(update_fields=['totp_secret'])
  return self.totp_secret

  Called every time the MFA setup page loads. Generates a fresh
  cryptographically random base-32 secret and persists it immediately
  so it is available for QR code generation and later verification.

----------------------------------------------------------------------
METHOD: get_totp_uri()
----------------------------------------------------------------------

  return pyotp.totp.TOTP(self.totp_secret).provisioning_uri(
      name=self.email or self.username,
      issuer_name="EduSecure",
  )

  Returns the otpauth:// URI in the standard format:
    otpauth://totp/EduSecure:username?secret=SECRET&issuer=EduSecure

  Microsoft Authenticator, Google Authenticator, and Authy all read this
  URI when scanning a QR code to set up an account.

----------------------------------------------------------------------
METHOD: verify_totp(token: str) -> bool
----------------------------------------------------------------------

  totp = pyotp.TOTP(self.totp_secret)
  return totp.verify(token, valid_window=1)

  valid_window=1 allows the token from the previous or next 30-second
  window to be accepted as well. This tolerates up to 30 seconds of
  clock drift between the server and the user's phone without requiring
  clock synchronisation.

PART 10 — accounts/views.py
================================================================================

----------------------------------------------------------------------
VIEW: register_view
----------------------------------------------------------------------

  Standard form-based registration. On POST with a valid RegisterForm,
  calls form.save() to create the User record (password is automatically
  hashed by Django's PBKDF2-SHA256). Redirects to login on success.

----------------------------------------------------------------------
VIEW: login_view  (Step 1 of 2-step login)
----------------------------------------------------------------------

  user = auth.authenticate(request, username=..., password=...)

  If credentials are wrong: show error, stay on login page.

  If MFA is enabled:
    request.session['mfa_pending_user_id'] = user.pk
    redirect to mfa_verify

    auth.login() is NOT called here. The user is not logged in yet.
    Their PK is stored in the session so the verify step knows who to
    finish logging in after the TOTP check passes.

  If MFA is not set up yet:
    auth.login(request, user)    — log in immediately
    redirect to mfa_setup        — prompt them to configure MFA

----------------------------------------------------------------------
VIEW: mfa_verify_view  (Step 2 of 2-step login)
----------------------------------------------------------------------

  user_id = request.session.get('mfa_pending_user_id')
  user = User.objects.get(pk=user_id)

  if user.verify_totp(form.cleaned_data['token']):
      del request.session['mfa_pending_user_id']
      auth.login(request, user)
      redirect to submission_list

  If the token is wrong: show error, stay on verify page.
  If no pending user in session: redirect back to login (prevents
  someone navigating directly to /accounts/mfa/verify/ without logging in).

----------------------------------------------------------------------
VIEW: mfa_setup_view  (QR code generation for Microsoft Authenticator)
----------------------------------------------------------------------

  secret = user.generate_totp_secret()    — fresh base-32 secret
  uri    = user.get_totp_uri()             — otpauth:// URI

  qr_img = qrcode.make(uri)               — generate QR image in memory
  buf    = io.BytesIO()
  qr_img.save(buf, format='PNG')
  qr_b64 = base64.b64encode(buf.getvalue()).decode()

  The QR code is rendered as a base64-encoded PNG embedded directly in
  the HTML template as a data URI:
    <img src="data:image/png;base64,{{ qr_b64 }}">

  No file is written to disk. No extra URL is needed to serve the image.

  When the user submits the 6-digit confirmation code:
    if user.verify_totp(token):
        user.mfa_enabled = True
        user.save(update_fields=['mfa_enabled'])

  MFA only activates after the user proves they scanned the QR correctly.

  The raw secret is also shown as text below the QR code as a fallback
  for users who want to enter it manually in their authenticator app.

----------------------------------------------------------------------
VIEW: logout_view
----------------------------------------------------------------------

  auth.logout(request)
  redirect to login

PART 12 — submissions/models.py
================================================================================

  class Submission(models.Model):
      student           = models.ForeignKey(settings.AUTH_USER_MODEL,
                                            on_delete=models.CASCADE,
                                            related_name='submissions')
      title             = models.CharField(max_length=255)
      submitted_at      = models.DateTimeField(auto_now_add=True)
      encrypted_content = models.TextField()
      hmac_digest       = models.CharField(max_length=64)
      vt_result         = models.TextField(blank=True)
      vt_safe           = models.BooleanField(null=True)

  encrypted_content
  — Stores the AES-256-GCM JSON blob (nonce + ciphertext + tag) as text.
  — The original file content can only be read by someone who has the key.

  hmac_digest
  — HMAC-SHA256 hex digest of the raw uploaded file bytes.
  — If the stored encrypted_content is ever modified in the database,
    the integrity check will fail on next read.

  vt_result
  — Human-readable message from VirusTotal (e.g. "File appears safe."
    or "ALERT: 3 malicious, 1 suspicious detections.").

  vt_safe
  — Boolean stored so the template can show a coloured badge immediately.
  — null=True means None is stored when VT timed out or errored,
    shown as "Unknown" rather than incorrectly marking the file safe.

  ordering = ['-submitted_at']  — newest submissions shown first

PART 13 — submissions/views.py
================================================================================

----------------------------------------------------------------------
VIEW: upload_submission
----------------------------------------------------------------------

  Full pipeline on POST:

  1. Read file bytes
     raw_bytes = uploaded.read()

  2. HMAC-SHA256 integrity fingerprint over raw bytes
     hmac_digest = compute_hmac(raw_bytes, key)

     Computed BEFORE encryption so it covers the original content.
     Any modification to the encrypted blob OR the original content
     will cause verification to fail.

  3. AES-256-GCM encrypt the content
     text_content = raw_bytes.decode('utf-8', errors='replace')
     encrypted = encrypt_aes_gcm(text_content, key)

     errors='replace' means binary files that are not valid UTF-8 are
     still stored (with replacement characters) rather than crashing.

  4. VirusTotal file scan
     uploaded.seek(0)                    — seek back to start after read()
     vt = scan_file(uploaded, uploaded.name)

  5. Save to database
     Submission.objects.create(
         student=request.user,
         title=form.cleaned_data['title'],
         encrypted_content=encrypted,
         hmac_digest=hmac_digest,
         vt_result=vt['message'],
         vt_safe=vt['safe'],
     )

----------------------------------------------------------------------
VIEW: list_submissions
----------------------------------------------------------------------

  Fetches all submissions belonging to the logged-in user.
  For each one, attempts to decrypt using decrypt_aes_gcm.
  If decryption fails (tamper detected — tag mismatch), plaintext is
  set to an error message and decrypted_ok is False.
  A 500-character preview of the plaintext is passed to the template.
  The template shows integrity and VT verdict badges per submission.
